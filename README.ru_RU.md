<h1 align="center">Own Backup</h1>
<p align="center">Резервное копирование дисков и томов Windows и Linux блок за блоком — и загрузочные носители, с которых их можно вернуть.</p>

**Own Backup** копирует диски и тома целиком, блок за блоком: в копию попадают
только занятые кластеры, а исключённые файлы не попадают вовсе. Копию можно
зашифровать паролем. Из копии восстанавливается раздел, диск или отдельные
файлы, а с загрузочного носителя — и тот диск, с которого загружается сама
Windows.

> **0.1.6-beta — предварительный релиз, первый с версией для Linux.** Важную
> копию проверьте восстановлением на запасной диск или в виртуальную машину,
> прежде чем на неё полагаться, — в Linux особенно: эта версия новая.

## Быстрый старт

1. Запустите установщик. Он регистрирует службу **Own Backup** — она делает
   всё, для чего нужны права администратора; само окно работает без них.
2. Откройте **Own Backup** из меню «Пуск» и создайте задание в разделе
   **«Резервное копирование»**: что копировать, куда, в каком формате и по
   какому расписанию.
3. Запустите задание и проверьте результат: **«Инструменты» → «Проверить
   образ»** или подключите копию как диск.
4. Соберите загрузочный носитель в **«Инструменты» → «Загрузочный носитель»**,
   пока компьютер работает, — системный диск восстанавливается с него.

Интерфейс — на русском и английском, темы светлая, тёмная и «Как в Windows».

## Возможности

- Полные, инкрементные и разностные копии томов и дисков целиком; задание
  может держать скользящее окно инкрементов — старейший вливается в базу.
- Читаются только занятые кластеры (NTFS, ReFS, FAT32, exFAT), у работающей
  системы — со снимка VSS.
- Три формата: **VHDX** (Windows подключает его сама), **qcow2** (сжатие zstd)
  и **OBK** (zstd и AES-256-GCM, открывается паролем или ключом
  восстановления).
- Исключения, которые действительно исключают: подходящие файлы не читаются, а
  записи о них удаляются из файловой системы внутри образа — пустых «призраков»
  не остаётся.
- Тома BitLocker, в том числе заблокированные, копируются расшифрованными — по
  паролю или 48-значному ключу восстановления.
- Контрольные суммы xxHash64 на каждый блок, проверка после копии или по
  требованию.
- Восстановление раздела или целого загрузочного диска вместе с записями
  загрузки UEFI; диск, с которого работает система, защищён от перезаписи.
- Загрузочный носитель собирается из среды восстановления самой Windows этого
  компьютера, интерфейс на нём тот же.
- Копия подключается как диск через встроенный в Windows инициатор iSCSI:
  сторонние драйверы не ставятся.
- Расписания и события (вход в систему, запуск, подключение диска назначения),
  повторы, пробуждение из сна, выключение после копии.
- Окно, командная строка и служба: служба работает от LocalSystem и отвечает
  по именованному каналу с ограниченным доступом.

## Текущие границы

- Исключения на NTFS/ReFS и FAT32/exFAT приняты живыми прогонами. Для
  ext2/3/4 и btrfs есть проверки файловой системы и тесты с монтированием и
  записью.
- На ext4, XFS и btrfs файл, который нельзя безопасно удалить, остаётся
  записью с обнулённым содержимым; итог запуска называет, сколько таких.
- Linux: работающий том копируется со снимка LVM или device-mapper. Занятый
  обычный раздел (корень ext4 без LVM и LUKS) на ходу не удержать — копируйте
  его с загрузочного носителя. Группа томов на нескольких дисках копируется
  только с предупреждением.
- Исключения внутри зашифрованного ReFS могут быть пропущены — с явным
  предупреждением в результате.
- У новых образов `.obk` два поколения заголовка. Носитель, собранный старой
  версией, их не откроет: пересоберите носитель этой версией.
- Тома BitLocker, защищённые только TPM, программа сама не открывает.
- На машине разработчика текущие планы и исторические доказательства хранятся
  локально в `.ai/`; эта папка не включена в репозиторий.

## Настройки и данные

| Что | Где |
|---|---|
| Программа | `C:\Program Files\OwnBackup` |
| Настройки, задания, история запусков, сохранённые ключи томов | `C:\ProgramData\OwnBackup` |
| Журнал службы, файл на день, хранится тридцать дней | `Logs\own-backup-service-<дата>.log` в папке программы |
| Что помнит окно: тема, язык | `%LOCALAPPDATA%\com.ownbackup.gui` |
| Резервные копии | там, где указано в задании; своих копий программа не держит |

В Linux программа лежит в `/usr/bin` и `/usr/libexec/own-backup`, настройки,
задания и ключи — в `/var/lib/own-backup`, журнал службы — в journald
(`journalctl -u own-backup`) и в `/var/log/own-backup`.

Повторный запуск установщика обновляет программу на месте. Деинсталлятор
оставляет настройки, если не сказать иначе, тихое удаление оставляет их
всегда, а резервные копии не трогает никто.

## Командная строка

```powershell
own-backup-cli.exe --help
own-backup-cli.exe list-disks
own-backup-cli.exe jobs status
own-backup-cli.exe verify D:\Backups\disk.vhdx
own-backup-service.exe /status
```

`own-backup-install.exe /S` ставит программу без вопросов; `/D=<папка>`
последним аргументом выбирает папку первой установки.

## Сборка

Rust 1.98.1 закреплён в `rust-toolchain.toml`; страницам окна нужен Node 24,
сборочным скриптам — `protoc`. На Linux для Tauri нужны пакеты из его
[списка](https://v2.tauri.app/start/prerequisites/).

```bash
cd crates/gui/frontend && npm ci && npm run build && cd ../../..
cargo test --workspace --locked
cargo xwin check --workspace --locked --target x86_64-pc-windows-msvc

sudo apt install nsis           # один раз, ради makensis
scripts/build-installer.sh      # target/dist/own-backup-install.exe
scripts/build-deb.sh            # target/dist/own-backup_<версия>_amd64.deb
scripts/build-linux-media.sh    # target/dist/own-backup-media_<версия>_amd64.iso
```

Пакет `.deb` собирайте в Ubuntu 24.04, самой старой поддерживаемой системе:
он требует те glibc и WebKitGTK, с которыми собран. Носителю нужны root,
`debootstrap` и зеркало Debian.

Последний скрипт собирает страницы окна и четыре исполняемых файла через
`cargo xwin` и упаковывает их NSIS
([packaging/windows/own-backup.nsi](packaging/windows/own-backup.nsi));
`--skip-build` упаковывает уже собранное. На Windows соберите
`cargo build --release --target x86_64-pc-windows-msvc` и запустите тот же
скрипт из Git Bash с `--skip-build`. VSS, DPAPI, iSCSI и прямой доступ к диску
кросс-компиляцией не проверить: `scripts/lab/run-installer.py` прогоняет
установщик в одноразовой виртуальной Windows, а восстановление диска
проверяется на машине с Windows или WinPE.

## Автоматические релизы

Тег версии, например `v0.1.6-beta`, запускает
[сборку релиза](.github/workflows/release.yml). Тег должен совпадать с версией
в `Cargo.toml`. GitHub собирает исполняемые файлы для Windows x64, упаковывает
установщик, ставит и удаляет его на сборочной машине, считает суммы SHA-256 и
публикует релиз только когда файлы готовы. Версия с суффиксом помечается как
предварительная. Сборку можно запустить и вручную — для существующего тега
или пробно, без публикации. Пакет и носитель для Linux собираются локально и
добавляются в релиз.
