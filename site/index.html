How it works

Not file by file. Block by block.

A backup keeps a partition or a whole disk the way it was, so it can be put back exactly — including the disk the system boots from. Own Backup reads the used blocks of the filesystem and writes them into one image file.

  • used
  • free — skipped
  • excluded — not read
  • 0blocks written
  • 0free skipped
  • 0excluded

  1. Freeze

    A snapshot first: VSS on Windows, LVM or device-mapper on Linux. Open files land in the copy in a consistent state.

  2. Read only what is used

    Free space is skipped. Excluded files are not read at all, and their names are removed from the filesystem inside the image.

  3. Compress

    zstd in qcow2 and OBK, level 1 to 19: a trade of size for speed.

  4. Encrypt

    OBK is encrypted with AES-256-GCM and opens with a password or a recovery key.

  5. Verify

    Every block has an xxHash64 checksum: check right after the copy, on a schedule or at any time.

What it can do

Everything a disk needs to come back

Full, incremental, differential

Volumes and whole disks — on a schedule, on an event or by hand. A job can keep a sliding window of increments, the oldest folded into the base.

A running system

Copied from a snapshot: VSS on Windows, LVM or device-mapper on Linux. Nothing has to be closed.

Exclusions that really exclude

Matched files are not read, and their entries are removed from the filesystem inside the image — not left as empty ghosts.

Encrypted archives

The OBK format: zstd and AES-256-GCM. It opens with your password or with the recovery key shown once at creation.

BitLocker and LUKS sources

BitLocker volumes, locked ones included, are copied decrypted — with the password or the 48-digit recovery key; LUKS volumes with their passphrase.

Windows ⇄ Linux

A backup made on one system opens, validates and restores on the other.

Restore a bootable disk

A partition or a whole disk, UEFI boot entries included — with a guard against overwriting the disk the system runs from.

A backup as a disk

Mount a backup and copy single files out. On Windows it goes through Windows' own iSCSI initiator: no third-party driver is installed.

Checksums on every block

xxHash64 in the image's own metadata. Verification needs nothing but the image.

Schedules and events

Logon, startup, a destination disk plugged in. Retries, wake from sleep, an optional shutdown afterwards. A busy action waits in a queue instead of being refused.

Boot menu

See and edit the UEFI boot entries: what the firmware offers and where it leads.

Linux partitions in Total Commander

A Windows plugin shows the files of ext2/3/4 and btrfs partitions of this computer, also inside LVM and LUKS — read-only and in place.

Versions and chains

Every run adds a version

A full version and the increments after it form a chain. The job's retention settings decide how chains grow and which versions go.

Blocks changed since the previous version. After a set number of versions a new full version starts the next chain; old chains are deleted whole once they are no longer needed.

Blocks changed since the last full version. Each differential depends only on its full version — and grows as changes pile up.

One chain: the oldest increment is folded into the full version, so there is always one full version and a sliding window of increments.

To restore an incremental version the program reads the whole chain under it. A chain is never longer than 60 images.

Restore and boot media

When the system will not start

The running system cannot overwrite itself. A boot medium is a small operating system with the same Own Backup window on it — started from a USB stick, a CD or an ISO.

Restore

  • a single partition;
  • a whole disk — with its partition table and boot code, so it boots again;
  • single files — mount the backup as a disk and copy them;
  • onto a new, empty disk or another computer.

The disk the system runs from and its EFI partition are protected from being overwritten.

Based on Windows Recovery Environment

Built on this computer from what is already on it: its own WinRE, the program with its window and, if you wish, this computer's drivers. Reads NTFS and ReFS natively.

Based on Linux (Debian 13 live)

UEFI with Secure Boot, or BIOS. The Linux window builds it and writes it onto a stick; the Windows window downloads it ready and checks it against the release's checksums.

Build it now, while the computer works — and check that the computer starts from it.

Disk cleanup

Less to copy, nothing removed blindly

Temporary files, error reports, crash dumps, caches, the Recycle Bin and the traces of work — on Windows and on Linux. The service does it, so the system's folders and the users' are both within reach.

  • Analysis first. Every item shows its size and the list of files; untick a file and it stays.
  • Profiles. Save a set under a name and pick it in a backup job — the disk is cleaned before the copy.
  • Automatic cleanup on a schedule, done by the service with no window.
  • Windows components by Windows' own handlers; on Linux — apt, logs and snap.

How it is built

Three programs, one local channel

The window and the service talk over a channel available to this computer only — a named pipe on Windows, a Unix socket on Linux — with an access token. No network port is opened.

Window

What you see: creates jobs, shows progress and history, starts restores. Runs without administrator rights and asks the service for everything.

Service

Does everything that needs administrator rights: reads disks, takes snapshots, writes and restores images, runs the schedule — also while the window is closed.

Command line

own-backup-cli — the same actions from a terminal or a script.

own-backup-cli
$ own-backup-cli jobs list
# The configured jobs, with their ids.
$ own-backup-cli jobs run 3f2a…
# Queues a job, like “Back up now”.
$ own-backup-cli verify "F:\Backup\Disk_C_Win11\Disk_C_Win11_disk4_inc_20261024-185102.obk"
# Validates an image (with its chain) against its checksums.

What it does not do

Honest about the edges

No cloud of its own

It does not copy to a cloud or over the network by itself: a backup is written to a folder — a local disk, a USB disk or a mounted network share.

No file sync

It does not synchronise files or keep versions of single files. To get one file back, mount the backup and copy it.

Nothing sent anywhere

No advertising, no telemetry, no update checks.
